# ארכיטקטורה

## זרימה

```
לקוח (PWA: נייד, טאבלט, מחשב)
  ├─ העלאת תמונות/וידאו ──► אחסון בענן
  │                           │
  │                     תור עבודות ──► Worker על GPU: ‏COLMAP → רשת (mesh)
  │                           │
  ├─ צפייה (model-viewer) ◄── מודל גולמי (GLB)
  │
  ├─ הכנה להדפסה ──► Worker: ‏trimesh/manifold: תיקון, קנה מידה, בסיס
  │
  ├─ מסך אישור מפורש (חובה)
  │
  └─ ייצוא STL/3MF ◄── קובץ סופי
```

יצירת המודל והכנתו להדפסה הם שני שלבים נפרדים, עם API ותור משלהם. כך אפשר להחליף את מנוע השחזור בלי לגעת בהכנה להדפסה.

## מה לקחת מוכן ומה לפתח

| שכבה | בחירה | רישיון | לקחת או לפתח |
|---|---|---|---|
| שחזור | COLMAP | BSD-3 | לקחת |
| שחזור, חלופה | Meshroom/AliceVision | MPL-2.0 | לקחת |
| צילום מודרך באנדרואיד | ARCore (מיקום המצלמה בקנה מידה מטרי) | Apache-2.0 SDK | לקחת (שלב 2) |
| שחזור על iOS | Apple Object Capture | קנייני, חינמי | אופציונלי, אחרי אנדרואיד |
| תצוגה | model-viewer | Apache-2.0 | לקחת |
| עורך (בהמשך) | three.js | MIT | לקחת |
| תיקון והכנה להדפסה | manifold + trimesh | Apache-2.0 / MIT | **לפתח מעליהם. זה הערך הייחודי של המוצר** |
| חשבונות ואחסון | Supabase (או Firebase) | — | לקחת |
| Slicing | OrcaSlicer CLI | AGPL-3.0 | שלב 2, רק אחרי החלטת רישוי |
| חיבור מדפסות | OctoPrint / Moonraker / PrusaLink API | — | שלב 3 |

## לא להשתמש

- ‏Gaussian Splatting של Inria ו-instant-ngp של NVIDIA: רישיון לא מסחרי.
- ‏NeRF ו-Splatting כפלט להדפסה: הם לא מייצרים רשת סגורה. אפשר להשתמש בהם לתצוגה בלבד, ב-gsplat (Apache-2.0).

## החלטות פתוחות

- עבודה עם AGPL: הפרדה לתהליך נפרד, או ויתור על slicing בענן לטובת הפניה לתוכנת ה-slicing של המשתמש.
- ספק GPU ועלות לכל סריקה. נמדד בשלב 0.
- אפליקציה נייטיב (Kotlin או Flutter) מול PWA בלבד, לשלב הצילום המודרך. **פלטפורמת היעד הראשונה היא אנדרואיד.**
- באנדרואיד אין שחזור איכותי על המכשיר ואין LiDAR ברוב המכשירים, ולכן השחזור חייב לרוץ בענן.
